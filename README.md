## 협업하며 배운 점

----------------------
병찬 : 서로가 맡은 클래스에 맞게 메소드를 구현하고 App에서 합치는 과정을 해보고 아래처럼 느꼈다.
현재는 4명이고 코드 자체도 작다보니까 충돌이 나더라도 해결하기 쉽지만, 사람이 많아지고 코드도 길어졌을 때 필수적으로
서로의 역할을 확실하게 나누고 그에 맞게 섬세하게 병합을 해야 나중에 편한다는 점을 배웠습니다.

----------------------
주희 : 지금은 사람이 적어서 충돌을 피하기 쉬웠지만, 다수의 팀원들과 협업을 할 때는 충돌을 피하기 위해서 팀원들과의 소통이 중요할 것 같다.

----------------------
다연 : 각자 맡은 파트를 lssue 로 공유하면 협업할 때 더 편리하고, 각자의 코드를 설명하면서 다른 사람의 코드도 한번 더 생각할 수 있었다.
각자의 코드를 설명하는 시간을 가지면서 도전 조건도 같이 이야기 하며 배울 수 있었다. 
충돌이 날 위험이 있으니 더 확실히 역할을 나누어 진행해야 한다는 점을 배울 수 있었다..
----------------------
석민 : 다른 작업자가 만들고, 사용한 메소드가 있을 경우 협업자가 일일이 메소드를 확인하며
무슨 역할을 하는지, 어느 변수를 받아서 사용하는지 추적하는 것은 비효율적이라고 생각되어서
모두가 자주 볼 수 있는 곳에 명세를 정립한 기획문서를 세우고 이후 다른 작업자의 메소드를
사용할 일이 있거나, 변수를 사용할 일이 있을때 같은 기능의 메소드가 중복되는 등의 작업 병목이
덜 일어나게끔 작업 설계를 해두는것이 중요하다고 느껴졌다.
